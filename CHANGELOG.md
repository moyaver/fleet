# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- Agent: the outbox kept every unacked event in memory, so a long run with no server (offline mode) or an unreachable one grew without bound (I10). The spool file is now the source of truth, read back into a small send window; when the 64 MiB spool (or the window, with no spool) is exhausted the agent stops storing event bodies and sequences a `journal.gap` instead (I5), and the spool starts over once everything in it is acked. `fleet-agent flush` streams the spool instead of loading it.
- Server: a new agent run opening while another run's batch in the same job was mid-transaction could deadlock in Postgres (attempt and job rows locked in opposite orders); the batch was retried and nothing was lost, but the agent reconnected. `open_run` no longer locks the attempt row (found by the Compose smoke test).
- `fleet-loadgen`: `wss://` servers panicked for want of a rustls crypto provider; it now installs ring, as the agent does.
- Agent: a late-starting observer could read a flow's console result before the log line that starts it and split one flow into two; it now catches up on the log before applying console output (found by the M3 end-to-end tests).

### Changed

- Relicensed from PolyForm Internal Use 1.0.0 to the GNU AGPL v3 (`AGPL-3.0-only`); a commercial license is available on request (ADR-0012).
- Renamed the product to Fleet; the agent binary is `fleet-agent` (ADR-0011).

### Added

- M5: retention (issue #45). The leader runs telemetry rollups (one-minute and one-hour, idempotent, late-data aware; unavailable readings stay unavailable), drops expired partitions of raw samples, the journal and steps (raw samples only once rolled up), deletes expired rollups and audit events, expires artifacts by retention class (failure evidence is promoted when its flow finalizes as failed; legal hold keeps an artifact), and deletes blob objects only when no artifact refers to them and after a grace period; leftover temp files of crashed local uploads are swept (`BlobStore::sweep_stale_uploads`). Migration 0009; `[retention]` server settings; operator guide section. The metrics endpoints serve ranges over 24 hours from the rollups.
- M5: failure fingerprints (flow identity + failing step + message with numbers, UUIDs, timestamps, durations, paths, serials and addresses removed, versioned `v1:`), condition fingerprints (device, Maestro `major.minor`, OS/arch, host class, CI provider; missing facts read `unknown`) and flaky v1 (confirmed: pass and fail on one commit and condition; suspected: flip rate ≥ 0.2 over the last 20 default-branch runs; inferred outcomes never count as passes) in `fleet-core`; migration 0007 and the ingest transaction store both fingerprints when a flow's outcome is final (ADR-0009).
- M5: `fleet-blob`: the `BlobStore` contract (content-addressed per project; streaming `put` that verifies size and SHA-256, ranged `get`, `head`, idempotent `delete`, `list` for GC) with a local filesystem backend (atomic writes) and an S3-compatible one (`object_store`, path-style, custom endpoint; Garage is the reference), one contract suite run against both; `fleet-blob::verify`: size, SHA-256, magic bytes per artifact class and archive safety for zip and `tar.zst` (entry count, expansion limits, unsafe paths, links, devices, nested archives); `[storage]` server settings and the operator guide's storage section. No upload endpoints yet.
- M3: `fleet-loadgen` runs simulated agents against a real server (`--agents --devices --storm --duplicates`), replacing `mock-server`; `fleet-e2e` proves the M3 exit criteria (50 agents × 4 devices, reconnect storm, server restart mid-run, fixture replay matching `fleet-agent inspect`, jobs and same-serial emulators kept apart); the Docker image (`deploy/docker/Dockerfile`, cargo-chef + distroless) and the Compose reference deployment (Postgres 18, Garage, Caddy); operator guide and protocol reference.
- M3: `POST /api/v1/agent/token` exchanges a CI OIDC token (configured issuers only, RS256, JWKS cached and refetched on an unknown `kid`, `aud`/`exp`/`nbf`/`iat` checked, each `jti` once) for a short-lived agent token, matched by trust policies on immutable repository IDs (`fleet-core::trust`; `pull_request_target` and `dynamic` always refused), or exchanges an API key. Verified claims name the pipeline run and job. The agent does the exchange on GitHub Actions (#25), tunnels through `HTTP(S)_PROXY` with `NO_PROXY` and trusts `FLEET_CA_FILE` (#24). `fleet-e2e` runs the real agent against the real server.
- M3: the live hub and `/api/v1/live` (snapshot, then deltas in version order per attempt, `resync` for slow subscribers, `Origin` check), REST snapshots with a consistent `version` (`/api/v1/projects`, `…/attempts`, `…/attempts/{id}`), `/api/v1/openapi.json`, liveness (`online`/`stale`/`disconnected`/`completed`) and leader-only sweeps that detach silent runs and abandon expired ones (open flows become `unknown` from `server_inferred`, jobs `interrupted`), and Fleet plans (`POST /api/v1/plans`, immutable, planned totals before any job starts; #21). Reads need a viewer token until browser SSO (M4). The plan manifest type moved to `fleet-protocol::plan`.
- M3: the server ingests agents: `/api/v1/agent/ws` (`fleet.v1+json`: welcome with server-authoritative resume, ack after commit, `event_rejected`, `seq_gap`, fencing, pings, idle timeout, `goaway` + close 1012 on shutdown), the HTTPS batch fallback `POST /api/v1/agent/batch`, telemetry checkpoints with `telemetry_ack`, API-key auth, `/livez` and `/readyz`, and the `serve`, `migrate`, `check-config`, `healthcheck` and `api-key create` subcommands with figment configuration (TOML, `FLEET_*`, `*_FILE`).
- M3: `fleet-store` with migrations 0001–0005 (Postgres 18) and the ingest transaction (epoch fencing, duplicate skip, ownership-checked upserts, claim-lattice outcomes, recorded gaps); `fleet-core::outcome` (suite and job outcomes); `cargo xtask sqlx`; CI runs the database tests against a Postgres 18 service.
- Protocol: `flow.ended` may name its flow (`flow`), so a claim about a flow that never started (a skipped `executionOrder` flow) creates it.
- M2: the `fleet-agent` CLI (`run`, `inspect`, `flush`, `check`, `version`): supervisor, live observer, spool, WebSocket transport, metrics, adb tracking, planner shards; `fleet-loadgen mock-server`; cargo-dist release pipeline.
- M1: `cargo xtask fixtures capture | import`, 24 Maestro 2.12.1 fixtures, Phase 0 flows, research 08; ADR-0003 accepted.
- M0 repository bootstrap: Cargo workspace skeleton, `cargo xtask` (setup, ci, lint, web), CI and CLA workflows,
  licensing and governance files, mdBook skeleton, and a Leptos hello page served by `fleet serve`.
