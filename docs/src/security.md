# Security model

Fleet authenticates browser readers through company OIDC and scopes publishers to one project. The role policy grants viewers access to runs and evidence. Publishers can ingest and upload evidence for their project. They cannot read private runs or artifacts.

## Secret export policy

I6 covers a measurable set of secret sources and representations. The agent collects values from `-e` and `--env`, flow-data `MAESTRO_*` variables, and environment names containing token, secret, password, passwd, pass, key, credential, auth, private, session or cookie. CLI configuration variables are excluded. Values shorter than four characters are excluded from global replacement because they occur throughout unrelated output.

Known values are replaced in plain text, JSON-escaped text, percent encoding with upper- or lowercase hex digits, and standard or URL-safe base64 with or without padding. Token patterns cover GitHub tokens, Fleet API keys, AWS access-key IDs, Slack tokens, bearer tokens, JWT shapes and PEM private keys. The captured Phase 0 planted secrets and adversarial encoding tests exercise these rules. The same redactor handles event text and exported text artifacts.

UI hierarchies are exported with the text they show hidden: the string value of every `text`, `accessibilityText`, `hintText` and `error` attribute becomes `[REDACTED]`, and the tree, its classes, bounds and resource IDs stay. The same redactor then runs over the result, so a known value is replaced wherever it appears. A hierarchy that is not JSON of the expected shape, or that cannot be redacted reliably, is not uploaded. `text` and `accessibilityText` appear in the captured fixtures; `hintText` and `error` are covered by a synthetic test only. Any other text attribute that Maestro adds later would pass through unredacted.

Device logcat excerpts of a failed flow are exported as a window: from 10 seconds before the failing step starts to 2 seconds after it ends, capped at 512 KiB. Each kept line goes through the same redactor, and the cap counts redacted bytes. When the cap cuts the window, the newest lines are kept. The log's clock is aligned with the failure using Maestro's own last line, and an excerpt whose clock cannot be aligned is not uploaded. Text that is not UTF-8 or contains NUL bytes is not sent.

Before exporting `commands.json`, Fleet withholds resolved `evaluatedCommand` payloads and variable definitions while retaining command types, status, sequence, depth and duration. This protects values created inside the flow that are absent from the runner environment.

Text artifacts must be valid UTF-8, contain no NUL bytes and fit within the 16 MiB per-file redaction limit. Otherwise the agent records `not_redactable` and sends no upload request. Redaction runs before hashing and transmission, so the digest identifies the exported bytes.

A secret assembled across distinct events or transformed with an unrecognized encoding may fall outside these rules. Flow configuration and test data should use synthetic accounts. A secret whose value is known only to the application can appear in logs and pixels. Stop evidence export with `FLEET_UPLOAD_ARTIFACTS=off` when those artifacts cannot be shared with project readers. Maestro's terminal output remains visible to the CI log consumer under the supervisor contract.

## Request limits

Sign-in, agent and viewer requests are limited per client address or per credential, and a refused request gets `429` with `Retry-After` ([operator guide](operator-guide.md#client-addresses-and-limits)). A viewer credential is charged only after it is accepted: a made-up token gets `401` and no limiter state, so random credentials cannot fill the limiter. Anonymous reads (`api.anonymous_read`, development only) are not limited, so enable them only for synthetic data.

## Uploaded files

Artifacts are untrusted input. Uploads are allowlisted by class, limited by size and run, and verified by size, SHA-256, content type and archive safety before storage. Storage keys include the project and digest. Requests authorize the project before exposing an artifact or issuing its signed URL.

Screenshots are sensitive binary media. The agent uploads failure screenshots, and their pixels receive no automatic redaction. Maestro's own `takeScreenshot` images and `startRecording` videos are not uploaded at all, because they cannot be redacted; adding them needs its own policy ([#133](https://github.com/moyaver/fleet/issues/133)). Project artifact permissions, retention and short-lived links control access. An authorized reader can retain a downloaded copy. The separate usercontent origin serves evidence with sandbox headers and no application cookies. Configure a distinct registrable domain in production. [Operator guide](operator-guide.md#usercontent-domain)

The export threats include secrets embedded in Maestro commands, unknown runtime values in logs, personal information in screenshots, malicious HTML, archive bombs, cross-project references and replayed upload grants. The controls above are exercised by redactor, uploader, artifact verification and project access tests. Retention removes Fleet's stored references and unreferenced blobs after the configured grace period. Backups retain data until their own retention expires.

## Threat review (research 06, T1–T21)

Reviewed for milestone M6 against the threat table in research 06 §6.1 (`research/06-ci-security-deployment.md`). Each row names the control in the code and the test that breaks if it goes. Status: **mitigated** means the control is enforced and tested; **accepted gap** is a known shortfall with a reason; **open** needs an owner's decision.

| # | Threat | Status | Control and evidence | Gap or follow-up |
|---|---|---|---|---|
| T1 | Fork PR steals publisher credentials | Mitigated for credentials | No credential means offline mode: no `FLEET_TOKEN` (an empty one counts as none) and no OIDC request. The run then connects to nothing, sends nothing, and keeps Maestro's output and exit code (`fleet-agent/src/net.rs` `has_credential`, `transport.rs` `run`; `tests/it/stream.rs` `a_run_with_no_credential_is_offline_and_sends_nothing`). Dangerous events are refused (`fleet-core/src/trust.rs`, `refusals_hold`; `tests/it/oidc.rs` `pull_requests_are_pr_trust_…`) | The offline bundle writer comes with `publish` (#83). No explicit `head.repo.fork` check |
| T2 | Same-repo PR forges results or poisons history | Mitigated | PR trust is decided on the server (`oidc.rs` trust and claims; `fleet-store` `agent_runs` stores trust). Claims are bound to `check_run_id`. Flow stats, the duration summary, the duration chart, failure groups and flaky inputs count only `trusted` runs (`screens/history.rs`, the `JOIN agent_runs` in `totals`, `chart_points`, `failure_groups`, `classifiable_runs`; `a_pr_failure_moves_neither_the_stats_nor_the_flakiness_verdict`) | A pull request run stays in the history and on its own run page. The `flaky_history` view itself is unfiltered, so a new reader must filter on trust. Results remain observability, not a gate: the CI exit code is authoritative (spec §16 item 11) |
| T3 | Stolen static token reused | Partly mitigated | Keys are stored as SHA-256 and revocable (`fleet-store/src/auth.rs`). A new key expires after `api.api_key_ttl_days` (90) unless `fleet-server api-key create --expires-in-days` says otherwise (`lib.rs` `key_expiry`; `config.rs` `api_keys_expire_in_90_days_unless_configured_otherwise`; `a_key_past_its_expiry_authenticates_nothing`) | Accepted gap: keys made before this change have no expiry, and there is no CLI to revoke or expire them (set `expires_at` or `revoked_at` in SQL). | T5 | Credential-bearing argv | Mitigated | `-e`/`--env` values are rewritten to `KEY=[REDACTED]`, and the value of every flag not on the safe list is redacted before the argv is recorded (`fleet-core/src/redact.rs` `redact_argv`; `fleet-maestro/src/invocation.rs` `is_safe_value_flag`, `is_boolean_flag`). Known values are redacted as before (`redact.rs`). Tests `unknown_flag_values_are_redacted_and_known_flags_keep_theirs`, `env_values_are_rewritten_to_key_and_marker`, `an_unknown_flag_without_a_value_does_not_swallow_the_next_flag` (`fleet-core`), `run_started_argv_never_carries_an_unclassified_flag_value` (`fleet-agent` session), `finds_secrets_in_argv_and_env`, `planted_secrets_never_reach_the_server` | A flow path that follows an unclassified boolean flag is recorded as `[REDACTED]`. A Maestro flag that takes a value is redacted until it is added to the safe list |
| T6 | Secrets in Maestro output | Partly mitigated | Exact-match redaction in plain, JSON, percent and base64 forms, plus token patterns (`redact.rs`). Text artifacts are redacted before hashing (`fleet-agent/src/upload.rs`). The server repeats the token patterns on step, flow, report and app-crash events before they are journaled or stored (`fleet-store/src/ingest.rs` `redact_log_text`; `a_token_in_log_text_is_stored_redacted_though_the_agent_sent_it_raw`) | Accepted gap: the server holds no known-secret set, so a value with no token shape that the agent failed to redact is stored. Text artifacts are not re-redacted on ingest, because that would change their hash. The minimum secret length is four characters (`redact.rs`), not six as research 06 suggests |
| T7 | PII in screenshots and videos | Accepted gap | Only failure screenshots are uploadable, and video is refused (`fleet-protocol/src/artifact.rs`). Retention uses `expires_at`. Served sandboxed (`usercontent.rs`, `a_screenshot_opens_inline_with_the_sandbox_headers_and_no_cookies`) | No audit of media access |
| T8 | Stored XSS through names, logs and steps | Mitigated | Text nodes only. `inner_html` is refused in Rust sources by `xtask lint` (`files` test). The dashboard CSP forbids `<object>` and `<base>` (`web.rs`, `plugins_and_base_urls_are_refused_outright`). ANSI is an allowlisted span model (`fleet-ui/src/logview/ansi.rs`) | No browser XSS corpus yet through flow names, step text and logs. The issue asks for one |
| T9 | User HTML runs in the app origin | Mitigated | Separate host with sandbox CSP (`artifacts/usercontent.rs`), host dispatch, and `html_is_shown_sandboxed_and_everything_else_is_a_download` | Config requires only a different host, not a registrable domain (`config.rs`). | T10 | Content sniffing: an image that is HTML or SVG | Mitigated | Magic bytes per class (`fleet-blob/src/verify.rs`). Content type comes from the verified kind (`artifacts/upload.rs`). An SVG whose root falls outside the head would pass as XML, still as an attachment |
| T11 | Zip bomb, traversal, symlinks | Mitigated | Archives are verified and never extracted (`fleet-blob/src/archive.rs`). Entry, size and ratio limits (`verify.rs`). Path, link and device checks, and nested archives refused. Tests `unsafe_entry_names_are_refused`, `links_and_device_files_are_refused`, `a_single_entry_zip_bomb_is_stopped_by_the_ratio` | None |
| T12 | Upload DoS and storage exhaustion | Mitigated | Per-run quotas of 2 GiB and 2,000 files, and per-project quotas of 20 GiB and 20,000 files declared in any 24 hours (`config.rs`, `artifacts/upload.rs`, `fleet-store` `declare`). Spool sweeper and retention (`sweeps.rs`, `retention.rs`). WebSocket and batch frames are capped at 256 KiB (`ingest.max_frame_bytes`). The agent fills each frame by bytes up to that cap (`outbox.rs` `after`, `transport.rs` `event_budget`), and an event over 192 KiB is stored as a gap, so no frame it sends can exceed the cap. Tests `a_run_cannot_store_more_files_or_bytes_than_its_quota`, `a_project_cannot_declare_more_than_its_daily_quota_across_its_runs` (`api/tests/artifacts.rs`), `frames_are_capped_at_256_kib_and_a_project_has_a_daily_quota` (`config.rs`), `a_batch_stays_within_the_frame_budget` and `the_largest_stored_event_leaves_room_in_a_frame` (`outbox.rs`) | The daily count scans the project's artifact rows from the last 24 hours with no index on `created_at`. Events of 192 to 256 KiB, which an agent used to send in a 1 MiB frame, are now gaps |
| T13 | Log injection (escapes, CR, fake lines) | Partly mitigated | Agent-side stripping drops CSI, OSC, DCS, SOS, PM and APC sequences with their payload (`fleet-maestro/src/stdout.rs`, `strings_are_removed_with_their_payload`). That covers the stderr notices and warnings (`supervisor.rs` `notice_line`), the job summary (`observer.rs`) and the `inspect`, `publish` and `check` output (`cli.rs`). Tests `a_line_that_starts_with_a_workflow_command_is_neutralized` (`ci.rs`) and `a_notice_with_a_line_break_cannot_start_a_workflow_command` (`supervisor.rs`) | Not neutralized: Maestro's own stdout and stderr pass through byte for byte, as I1 requires (`supervisor::output_is_byte_exact`). | T14 | SSRF | Partly mitigated | The server fetches no agent or user URL. Report links are displayed. The JWKS client does not follow redirects, as the login client does not (`oidc.rs` `Jwks::new`; `a_redirected_discovery_document_is_not_followed`) | Accepted gap: the `jwks_uri` from the discovery document is not checked against the issuer. The issuer is admin-configured, and some IdPs host JWKS on another host |
| T15 | Signed link leakage | Mitigated | Links are HMAC-signed over project, artifact and expiry (`artifacts/links.rs`) and minted only after the read check (`artifacts/list.rs`). `Referrer-Policy: no-referrer` (`usercontent.rs`). TTL capped at 300 s (`config.rs`, `a_signed_link_lives_at_most_five_minutes`) | Links are not bound to a user ID (optional in research 06) |
| T16 | IDOR across projects | Mitigated | Every read is scoped by project (`api.rs` `read_project`; `fleet-store` queries filter on `project_id`). Upload content and completion are scoped to the publisher's project. The authorization matrix (`api/tests/authz_matrix.rs`) walks every route for every principal, and `access.rs` covers the object routes | None |
| T17 | Cross-site WebSocket hijacking | Mitigated | `Origin` is checked on upgrade (`api/live_ws.rs`, `session.rs` `same_origin`). | T18 | Compromised agent binary | Accepted gap (process) | Actions are pinned by SHA (`release.yml`, `image.yml`). Checksums are in `ci.yml`. | T21 | IdP group-claim mishandling | Mitigated | Default deny with no mapped group (`login.rs`; `login/tests.rs`, `without_a_group_that_maps_to_a_role_there_is_no_access`). **Summary.** Of the 21 threats, 11 are mitigated (T1 for credentials only), 3 are partly mitigated (T3, T6, T14), 7 are accepted gaps (T18 and T19 are process items), and none is open. Fixes made in this review: the dashboard CSP (T8), a `jti` required on CI tokens (T4), SVG with an XML prolog refused (T10), OSC and string sequences stripped (T13), signed links capped at 300 s (T15), live sockets closed when their sign-in ends (T17, T21), the `inner_html` lint (T8), the authorization matrix (T16), pull request runs kept out of stats and flakiness (T2), an agent with no credential runs offline (T1), API keys expire by default (T3), no redirects on the JWKS client (T14), and token-shaped text in log events redacted on ingest (T6).

**Not covered by the issue's "done when" yet.** A browser XSS corpus through flow names, step text and logs (T8) is still open. The fork-PR offline path is tested (T1).

**Other behaviour.** The agent WebSocket upgrades for anyone and refuses unauthenticated handshakes with a `reject` frame, so no human or anonymous caller gets past the handshake. The authorization matrix checks this (`agent_socket_as`).

## Rate limits (#118, #35)

Each configured limit has a test that refuses the request with `429` and `Retry-After`. The tests run in the server's integration suite (`crates/fleet-server/tests/it/ratelimit.rs`) and the limiter's unit tests (`limits.rs`).

| Limit (`rate_limits.*`) | Test |
|---|---|
| `ip_requests_per_minute`, `ip_burst` (pre-auth) | `the_token_endpoint_limits_one_client_ip_and_says_when_to_retry`; `behind_a_trusted_proxy_each_forwarded_client_gets_its_own_bucket`; `a_spoofed_forwarded_for_from_an_untrusted_peer_does_not_escape_the_limit`. Browser sign-in shares this limiter and has no test of its own |
| `credential_requests_per_minute`, `credential_burst` | `a_credential_is_limited_on_batch_connections`; `a_credential_is_limited_on_socket_upgrades` |
| `events_per_second`, `event_burst` | `a_fast_agent_is_slowed_and_no_event_is_dropped` |
| `viewer_requests_per_minute`, `viewer_burst` | `a_viewer_token_is_limited_on_reads_and_says_when_to_retry`; `a_viewer_token_is_limited_on_live_upgrades_and_says_when_to_retry`; `two_viewer_tokens_have_separate_buckets` |
| `max_tracked_keys` | `keys_are_independent_and_a_busy_table_refuses_strangers_only`; `idle_keys_are_forgotten_so_memory_stays_bounded` (`limits.rs`) |
| The refusal itself | `a_refusal_is_429_with_retry_after` (`limits.rs`) |

On the agent side, `a_rate_limited_agent_waits_for_retry_after_and_the_run_keeps_maestros_status` and `a_rate_limited_batch_waits_for_retry_after_and_the_run_keeps_maestros_status` (`crates/fleet-agent/tests/it/stream.rs`) show that a `429` slows the upload and never changes the run.
